## The `components/postgres` Pattern

Located at: `kubernetes/components/postgres/`

### How It Works

The component uses **kustomize component injection** via the Flux Kustomization's `components:` field. It:

1. **Bundles a Per-App CNPG Cluster** — Each app gets its own `3-instance CNPG cluster` (not shared) with:
   - Per-app Barman backup archive (s3://cnpg18-per-app-backups/${APP})
   - Recovery bootstrap from that backup archive
   - 5Gi storage, control-plane affinity, anti-affinity across nodes
   - Per-app DB init via `postgres-init` container (from secret)

2. **Injects Resources** — The component adds:
   - `cluster.yaml` — A CNPG `Cluster` resource with `${APP}` variable substitution
   - `externalsecret.yaml` — ExternalSecret for DB credentials
   - `scheduledbackup.yaml` — Automatic backups

3. **Variable Substitution** — Flux Kustomization `postBuild.substitute` maps:
   - `${APP}` → app name (e.g., `radarr`)
   - `${APP}-backup-archive` → Barman archive name

### Current Usage

## Migration Plan

### Phase 1: Preparation & Audit

**Step 1.1 — Identify all databases per app**
Each app using `postgres18-rw.database.svc` has its own database(s). Map them:

| App | Database(s) | Schema |
|-----|------------|--------|
| Radarr | radarr_main, radarr_log | Main + log DB |
| Sonarr | sonarr_main, sonarr_log | Main + log DB |
| Lidarr | lidarr_main | Single DB |
| Prowlarr | prowlarr_main | Single DB |
| Whisparr | whisparr_main | Single DB |
| Paperless | paperless | Single DB |
| Seerr | seerr | Single DB |

**Step 1.2 — Verify Barman backup compatibility**
The `components/postgres` component expects Barman backups on MinIO. Ensure the MinIO operator has the capacity for per-app backup archives (current: 1 shared archive for all apps).

**Step 1.3 — Inventory ExternalSecrets**
Each app's DB credentials are in 1Password via `cloudnative-pg` ExternalSecret. These need to be migrated to per-app secrets (e.g., `radarr-postgres` with keys `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`).

### Phase 2: Migrate One App (Pilot)

**Pick Paperless** — it already uses `postgres-init` for init and has a single database.

**Steps:**
1. Add `components/postgres` to `paperless/ks.yaml`:
   ```yaml
   components:
     - ../../../../components/valkey
     - ../../../../components/volsync
     - ../../../../components/postgres   # NEW
   ```
2. Remove `dependsOn: cloudnative-pg-cluster18`
3. Add `postBuild.substitute`:
   ```yaml
   postBuild:
     substitute:
       APP: paperless
   ```
4. Remove `PAPERLESS_DBHOST` and `INIT_POSTGRES_HOST` from the ExternalSecret (they're now auto-generated by the component)
5. Remove the hardcoded `postgres18-rw.database.svc.cluster.local` from the app's env vars
6. Apply and verify: Pod starts, connects to new cluster, data intact

**Verification:**
```bash
kubectl exec -n media deploy/paperless -- pg_isready -h paperless-rw.default.svc.cluster.local
# Should succeed

# Verify backup
kubectl get scheduledbackup -n media paperless
```

### Phase 3: Migrate Radarr/Sonarr Family (Jellyfin Stack)

These are the most numerous apps and share the same pattern:

1. **Create per-app ExternalSecrets** in 1Password (or generate via the component's pattern):
   - `radarr-postgres` with `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`
   - Same for sonarr, lidarr, prowlarr, whisparr, seerr

2. **Update each `ks.yaml`:**
   ```yaml
   components:
     - ../../../../components/volsync
     - ../../../../components/postgres
   dependsOn: []  # remove cloudnative-pg-cluster18
   postBuild:
     substitute:
       APP: radarr   # or sonarr, lidarr, etc.
   ```

3. **Update externalsecret.yaml:** Remove the `cloudnative-pg` dataFrom and DB host template vars

4. **For Radarr/Sonarr** — Note these have TWO databases (main + log). The `components/postgres` component handles single DB via `bootstrap.recovery.database: ${APP}`. For two-DB apps, either:
   - **Option A:** Split into two databases — run two component patches (one per DB)
   - **Option B:** Keep main + log as separate DBs in a single cluster by adding post-init SQL

### Phase 4: Cleanup

1. **After all apps migrated:**
   - Delete `cluster18/cluster18.yaml`
   - Delete `cluster18arm64/cluster18arm64.yaml`
   - Comment out `cloudnative-pg-cluster18` and `cloudnative-pg-cluster18arm64` in `ks.yaml`
   - Decommission the old shared clusters

2. **Keep `postgres-vector`** — Immich depends on it and it has vchord extension

3. **Update all `ks.yaml` files** that reference `cloudnative-pg-cluster18` in `dependsOn`

### Rollback Plan

Each app can rollback in <5 minutes:
1. Restore ExternalSecret to point back to `postgres18-rw.database.svc`
2. Remove `components/postgres` from ks.yaml
3. Re-add `dependsOn: cloudnative-pg-cluster18`
4. Flux will reconcile back

## Migration Risk Assessment

| Risk | Mitigation |
|------|-----------|
| Data loss during switch | Barman backups exist; CNPG recovery from backup is tested |
| Downtime | CNPG failover is <30s; app-init container handles schema migration |
| Backup inconsistency | Per-app backups are independent; no cross-app restore dependency |
| 1Password credential mismatch | Test with one app (Paperless) first; script creation for others |
| Storage expansion | Each cluster gets 5Gi (current shared is 20Gi per app's data) — may need to increase if apps have grown |

## Storage Impact Comparison

| Current (Shared) | Migrated (Per-App) |
|-----------------|-------------------|
| 3 clusters × 20Gi = 60Gi total | ~12 apps × 5Gi = 60Gi + postgres18-arm64 + postgres-vector |
| Single point of failure | Each app has independent HA (3 replicas) |
| Barman: single archive | Barman: 1 archive per app (more overhead, more safety) |
| Shared resource contention | No cross-app resource contention |

## Recommended Approach

1. **Start with Paperless** — single DB, already uses postgres-init, good pilot
2. **Then migrate the Jellyfin family** (Radarr/Sonarr/Lidarr/Prowlarr/Whisparr) in groups of 2-3
3. **Then Seerr** — single DB, straightforward
4. **Decommission shared clusters last** — after all apps verified
